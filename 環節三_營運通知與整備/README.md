# 環節三：營運通知與車輛整備流程

> 目標：設計流程與機制，讓客服及營運人員可以**即時得知車況**（車輛清潔或車損），安排後續車輛整備及清潔。

## 狀態：已有可操作雛形，完整服務流程設計中

### 已完成（隨環節二一併交付）

- **複核後台 Demo**（38 個真實案例、可上台操作）：https://claude.ai/code/artifact/ea7e3f69-18d6-4e5d-bbc2-2d6dd4025058
  - P1 即時預警／P2 工單／P3 記錄三級路由，紅橙綠色條佇列
  - 借/還照並排 + AI 標註框（直接圈出損傷/髒污位置）+ 判定理由
  - 一鍵裁決：確認車損→自動帶照片證據鏈進索賠；確認髒汙→派遣清潔、該車暫停派單；駁回誤報→回寫為訓練資料
- **預警分級與 SLA 設計**（架構文件 §05）：P1 ≤5 分鐘通知站點/客服、P2 ≤4 小時工單、缺圖案件當日補件清單

### 待完成

1. **正式通知管道**：LINE Notify / 簡訊 / 站點端推播的實際接入（Demo 目前以後台工單呈現）
2. **清潔調度整合**：髒汙車輛自動排入清潔班表、完成後解除派單鎖定的閉環
3. **整備看板**：以車輛為中心的狀態流轉（正常 → 待複核 → 待整備 → 整備中 → 恢復派單）
4. **用戶端體驗**（加分題方向）：乾淨還車的信譽加分/回饋、爭議發生時的照片證據自助查詢
