# Demo Script — 複核後台（2 分鐘）

Demo 網址：https://claude.ai/code/artifact/ea7e3f69-18d6-4e5d-bbc2-2d6dd4025058
（建議事先開好分頁；資料內嵌於頁面，載入後不需網路請求）

## 事前準備
- 若前次排練留有複核紀錄：開 DevTools Console 執行 `localStorage.removeItem('irent-review-demo-v1')` 後重新整理，KPI 歸零。
- 預先確認三個指定案例位置（佇列依 P1→P2→P3 排序，車牌用 ⌘F 可找）。

## 流程

### ① 開場總覽（20 秒）
畫面：KPI 列 + 佇列。
講：「這是客服每天早上看到的畫面：32 件待複核，21 件 P1 即時預警、3 件 P2 工單。左邊佇列紅橙綠色條就是分級，全部是真實照片和真實 AI 判定。」

### ② 案例一：RFB5176 右後 — AI 抓到未索賠車損（40 秒）
操作：點佇列中 RFB5176 右後（P1）。
講：「借車照、還車照並排——右後保桿這裡多了藍色擦撞痕。AI 給 0.98 信心，理由寫得很清楚：『借車照同位置漆面完整乾淨』。注意右上角標籤：這台車當時『未索賠』——是 AI 幫營運端把漏掉的錢找回來。」
操作：按 <kbd>1</kbd> 確認車損 →「一鍵確認，系統自動帶照片證據鏈進索賠流程。」

### ③ 案例二：任select一筆索賠 P1（如 RDL-8265 右後）（30 秒）
操作：↑↓ 鍵切到該案件。
講：「正常流程長這樣：AI 標出位置、類型、嚴重度和理由，客服眼睛確認、鍵盤裁決，一件幾秒鐘。」按 <kbd>1</kbd>。「注意上方 KPI 的已複核數即時在動——每一次裁決都回寫成訓練資料。」

### ④ 案例三：P2 無法比對（如 RDX-1085 右前）（30 秒）
操作：篩選鍵點「P2 工單」，點開 RDX-1085。
講：「AI 不會硬猜。這件借車照根本沒拍到右前保桿，模型回報『無法比對』，走補件流程——這正是我們主張把檢核前移到拍攝端的原因。」按 <kbd>3</kbd> 要求補件。

### ④b 車內整潔（20 秒，時間充裕才展示）
操作：篩選鍵點「車內整潔」，點 RDK-0263 後車內。
講：「同一套後台也管車內整潔：座椅上的碎屑污漬被判『髒汙』，確認後直接派清潔、該車暫停派單。」

### ⑤ 收尾（10 秒）
操作：點篩選「已複核」。
講：「複核完的案件在這裡形成閉環——確認的進索賠，駁回的變成負樣本，系統越用越準。」
