# 使用者流程

## 租客（一般用戶）
```
還車 → App 引導拍 6 張照（4 方位 + 前/後車內）
→ 上傳即完成還車（AI 判定非同步，不用等）
→ 無異常：無感通過，車輛乾淨可回饋信譽加分
→ 有疑慮：收到補拍推播（照片沒拍到部位時）
→ 有爭議：索賠通知附借/還對照照片證據，透明有依據
```

## 站點 / 清潔調度（環節三，已實作於整備中心）
```
客服確認「髒汙」或「車損」→ 自動開清潔／維修任務 + 系統推播（webhook）
→ 站點人員手機版 /ops/m：選組別 → 看到指派給我／未指派的任務
→ 「接單並開工」（防搶單）→ 拍完工照 → 「完工」（清潔任務無照片不能完工）
→ 車輛派單狀態自動由「整備中・不可派」變回「可派」（模擬，未接派單系統）
→ 完工照成為該車下一次借車比對的基準照
（下一位用戶不再拿到髒車；下一次比對不再只靠用戶自拍）
```

## 客服 / 複核人員（Demo 主角）
```
開啟複核後台 → KPI 總覽（待複核 / P1 / P2）
→ 佇列依等級排序，紅橙綠色條一眼分流
→ 點開案件：借車照 vs 還車照並排
→ 讀 AI 判定卡：損傷位置/類型/嚴重度/信心 + 判定理由
→ 一鍵裁決：
   ✓ 確認車損 → 自動帶照片證據鏈進索賠
   ✕ 駁回誤報 → 回寫為訓練樣本
   ⟳ 要求補件 → 推播用戶補拍
→ 鍵盤 ↑↓/1/2/3 快速操作，秒級處理一件
→ 【整備中心 /ops】通知中心只列需要行動的事（新任務／推播失敗／SLA 逾時）
→ 任務詳情：指派、SLA 倒數、三對象文案生成→修改→發送、處理歷程與備註
```

## 營運管理層
```
整備看板：待處理 → 處理中 → 已完成，拖曳推進，逾時紅字
營運洞察：真實上傳 log 4,820 單的還車時段分布 → 清潔人力排 15–23 時、維修排凌晨
          整備中位開工／完工時間、車輛事件排行、人工裁決 vs AI 一致率趨勢
通知設定：管道狀態（不外洩 URL）、SLA 門檻、完工照規則、逾時升級、預設指派
→ 每次複核累積標註 → 模型持續變準 → 人工複核量遞減
```
