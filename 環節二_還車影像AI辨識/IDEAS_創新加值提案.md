# 環節二 創新加值提案（待開發點子庫）

> 狀態：已討論、未實作。優先序見文末。

## 1. 車輛損傷護照（Damage Passport）⭐ 首選 ✅ 已實作雛形（2026-08-20）
- 實作：build_passport.py（36 台車建檔，9 台掛真實訂單）、passport_judge.py（護照感知判定）
- 實驗結果：既有損登錄後仍 3/3 票抓到新增大損（RCR-7661 正向對照）；新舊難分案例判定由翻轉不定變穩定（RDH-3092）
- Dashboard 新增「車輛損傷護照」頁：俯視圖損傷定位、責任訂單追溯、證據照連結
每台車一份累積的損傷指紋檔案：每次還車判定的損傷（位置 + 標註框 + 時間 + 訂單號）自動歸戶。
- 責任歸屬變時間軸查詢：「這道刮痕最早出現在哪一單」直接回溯
- 治本解決唯一漏抓型態（RDH-3092 型舊損密集、新舊難分——有護照不用每次重判舊損）
- 可視化：車輛展開圖標損傷點隨時間累積
- **可行性：兩日資料內同車已有多筆訂單，現有資料可 demo 概念**

## 2. 還車 30 秒「車況收據」⭐ 與 1 組合拳
辨識結果推給用戶：還車後 30 秒收到「本次租期無新增車損 ✓ 車內狀況良好 ✓」。
- 爭議前置消解（用戶知道被公平對待）；乾淨還車累積信譽分換優惠
- 成本趨近零：判定本來就在跑，只是多發通知
- 對內損傷護照 + 對外車況收據 = 同一份資料一魚兩吃

## 3. 照片作弊偵測 ⭐ 最快出驚喜數字
舊照重用、翻拍螢幕、同圖交差：感知雜湊（pHash）比對用戶歷史上傳 + EXIF 時間戳 vs 訂單時間核對。
- **可立即實測：手上 27,367 筆真實上傳紀錄，一個下午能掃完重複照片率**
- 若掃出真實案例，簡報從「假設風險」變「我們發現了 X 筆」

## 4. 車隊損傷熱點分析
聚合所有判定：最常受損部位、站點髒污率、時段分布。
- 從單張判定升維到營運洞察（右後最常受損 vs 右後漏拍率最高的交叉分析很有故事）
- 現有 141 組判定 + xlsx 就能畫第一版圖表

## 5. 損傷自動計價建議
標註框已有位置/類型/嚴重度 → 加一層維修/清潔費初估（部位 × 類型 × 面積）。
- 複核介面顯示「建議求償 NT$X,XXX」，客服一鍵帶金額進索賠

## 6. 現場實測入口（任意照片即時判定）⭐⭐ demo 主力・待做
現況所有判定腳本都綁死資料集（pairs.json / interior_sample.json / case_id），沒有「隨便給兩張照片就能判」的入口。
- CLI：`judge_photos.py 借車照 還車照` → Quality Gate → 級聯判定 → 視覺標註
- 網頁：監理台加「現場實測」分頁，拖拉上傳兩張照片即時判定（`POST /api/judge`）
- 價值：破解「結果是不是挑過的」質疑，可請評審當場拿手機拍的照片來測
- 詳細規格見 `隊友開工須知.md` §6.1

## 建議優先序
1. **⑥ 現場實測入口**：demo 說服力最高，且讓其他所有功能都能被現場驗證
2. **①+② 組合**（損傷護照 + 車況收據）：營運效率與用戶體驗雙殺，資料現成
3. **③ 重複照片掃描**：半天可完成，可能產出簡報級的驚喜數字
4. ④ 熱點分析（簡報加分頁）→ ⑤ 計價建議（需費率表輔助）
