## Prompt 架構規格落地（觀測覆蓋度 → 加權判定 → 估價 → 文案）

依《環節二 AI 判讀 Prompt 架構規格 v1.0》實作的分階段流程。核心是回答一個
其他做法多半沒處理的問題：**你怎麼確保系統不會冤枉用戶？**

| 階段 | 模組 | 做什麼 |
|---|---|---|
| 共用詞彙 | `taxonomy.py` | 38 分區代碼／11 損傷類型／信心校準定義／車內區域與髒汙元素；所有 prompt 的代碼表由此單一來源產生 |
| **S1 觀測覆蓋度** | `coverage.py` | 對【借車照】逐分區評觀測品質 0–1 + 環境旗標（水痕/反光/逆光/遮擋）。回答「這張基準照到底看清楚了哪些部位」 |
| **S4 差集加權** | `diff_new_damage.py` | 新損信心 × 基準觀測品質 → 處置層級。**上次沒拍清楚的部位，這次不得對用戶主張** |
| **S6 估價分流** | `disposition.py` | 純規則表零 API：損傷×尺寸×材質 → 維修動作 + 級距 A/B/C/D + 估價區間；並算出「不值得追」的案件 |
| **S7 多對象文案** | `notify.py` | 同一判定產出用戶／客服／派工單三種語氣，附程式面 grounding 查核（防杜撰金額與歸咎表述） |
| S2 偵測 prompt v2 | `detect_v2.py` | 規格版偵測 prompt（先描述後判斷／主動排除混淆源／UV 座標），**與現行判定並存**，由 `compare_prompts.py` A/B 對照 |

```bash
python3 pipeline/coverage.py --pairs              # 建立 141 組借車照觀測基準
python3 pipeline/diff_new_damage.py --calibrate   # 依實際分布校準門檻
python3 pipeline/diff_new_damage.py --apply       # 套用並輸出影響分析
python3 pipeline/disposition.py --table           # 維修對照表與估價級距
python3 pipeline/disposition.py --thresholds 120 8  # 告警量預算反推門檻
python3 pipeline/notify.py --demo                 # 三對象文案生成
python3 judge_photos.py 借.jpg 還.jpg --coverage --angle 左後   # 現場實測加跑加權
```

### 實測結果與兩處刻意偏離規格

跑完 141 張借車照的 Stage 1，得到 **1,476 筆分區觀測品質**（p10=0.45／p50=0.65／p90=0.75）。
這組實測數字推翻了規格的兩個預設：

**① 門檻不可照抄**：規格設 `prior_q ≥ 0.8` 可自動處置，該值預設基準照是營運人員的高品質
入隊拍攝。本資料集為用戶手持拍攝，**≥0.8 只占 0.1%**——照抄等於自動處置永遠不會發生。
門檻改以資料集分位數校準為 0.70／0.50。

**② 相乘式加權數學上不可用**：規格的 `信心 × prior_q`，因 prior_q 最大僅 0.75，
乘積上限 0.74 **永遠達不到 0.85 門檻**——27 筆偵測全數降級（含 21 筆確認真損），
只擋到 1 筆誤報。改為**兩道獨立門檻**（偵測信心 ≥0.85 且 prior_q ≥0.70）後：

| 分流結果 | 規格相乘式 | 兩道獨立門檻 |
|---|---|---|
| 自動處置 | 0 | **13** |
| 人工複核 | 21 | 8 |
| 被降級的真損 | 21 | 9 |

> ⚠️ **誠實限制**：在本資料集上，這層機制降了 9 筆真損、抓到 0 筆誤報——
> 它**沒有提升準確率**，簡報不可如此宣稱。其價值是結構性的：用戶申訴時能證明
> 「借車照確實拍得到該部位」。要在「基準照被遮擋而誤告用戶」的資料上才量得出效益。

### ③ S2 規格版 prompt 全量實測：**落敗，不予採用**

141 組跑滿後對照人工重標（n=138）：

| | 現行 prompt | v2 規格版 |
|---|---|---|
| Recall | 95.5%（21/22） | **100%**（22/22） |
| FPR | **0%** | 3.5%（4 筆誤報） |
| Precision | **100%** | 84.6% |

v2 用 **4 筆新誤報**換到 1 筆真損。本專案第一指標是「申訴推翻率」，
誤告用戶是最不可接受的失敗模式——這個交換不划算，`results_config.py` 維持指向現行判定。

**且無法靠信心門檻救回**，v2 的誤報都是高信心的：

| 信心門檻 | Recall | FPR |
|---|---|---|
| 0.75 | 100% | 2.6% |
| 0.85 | 90.9% | 0.9% |
| 0.90 | 63.6% | **0%** ← 要壓到零誤報，recall 崩到 63.6% |

沒有任何操作點優於現行的 95.5%／0%。人工逐張看圖複驗 RDL7827-左前：
v2 宣稱左側裙「大範圍塑膠件破裂、斷裂外翻」，實際照片該處完好——
把輪拱陰影幻覺成嚴重結構損壞。**高信心杜撰嚴重損傷**正是會造成錯誤索賠的失敗模式。

### ④ 把兩項修法單獨移植回現行 prompt（v4）：**同樣落敗**

既然整包換掉不行，就只移植「既有損對稱舉證」與 `ruled_out_basis` 兩項，
其餘判定準則一字不動（`SYSTEM_V4`，見 `run_eval_gemini.py`）。141 組跑滿：

| | 現行 prompt | v4 移植版 |
|---|---|---|
| Recall | **95.5%**（21/22） | 95.5%（21/22） |
| FPR | **0%** | 3.5%（4 筆誤報） |
| Precision | **100%** | 84.0% |

**★ 核心教訓：強制舉證欄位擋不住幻覺，只會讓幻覺變得更有說服力。**

v4 確實救回了 RDH-3092——修法本身有作用。但它同時**漏掉了 RCG2235-右後**，
正是這個修法要防的那種失敗。模型乖乖填了欄位：

> `seen_in_pickup_photo`:「借車照中右後保桿紅色反光片右側及底部邊角處已存在相同的黑色擦痕」
> `pickup_evidence_strength`: **clear**

人工逐張看圖確認：**借車照該處是乾淨的，這段敘述是杜撰的。**
30 筆既有損主張中 **28 筆自評 `clear`、0 筆 `cannot_confirm`**——
逃生出口沒有被關掉，只是換了個有自信的標籤。

另新增的 4 筆誤報中有 3 筆（RDL7827、RDU-5572、RDW-7085）與 v2 幻覺的是**同一批照片**：
兩個不同 prompt 在同樣的照片上編出同樣的損傷。

> **結論**：`judge()` 預設維持 `v4=False`，`results_config.py` 不變，現行判定不動。

`ruled_out_basis` 在 v2 全量測試中確實有效（平均 6.0/6「全部勾滿」→ **2.45/6、全部勾滿 0%**，
每筆都有具體理由），但它改善的是輸出可讀性，不是判定準確率。

**規格的信心校準完全無效**：加了校準定義與 three-shot 文字範例後，
42 筆損傷仍有 29 筆 ≥0.9、僅 1 筆落在 0.6–0.74。要修需 image few-shot 或後處理校準。

詳見 `diff_new_damage.py` / `detect_v2.py` 檔頭。

### ⑤ 第四、五次證偽：v5 與外部驗證反向查核

**v5（只加 `ruled_out_basis`，不動任何判定準則）**：四次 prompt 改寫中最差。
Recall 95.5% → **81.8%**（掉 13.7pp）、FPR 2.6%，7 組翻轉全是退步。
它只要求模型「把已經做過的排除思考寫出來」——結論是**要求模型解釋自己的推理，
會讓推理本身變差**。可解釋性一律由判定之後的層產生（S6 規則表理由、S7 文案），
絕不在判定當下要求模型自我解釋。這正是 S6/S7 純加分、四次 prompt 改寫全敗的分野。

**外部驗證反向查核（`reverse_check.py`，2026-08-28）**：v4 落敗時推測的出路——
對每筆「判無新損＋帶既有損主張」發起獨立呼叫、**只給借車照**、只問「描述所指的
痕跡是否可見」——實測後也證偽：

| | flash | pro |
|---|---|---|
| 攔截逃生出口案例（RDH-3092、RCG2235-v4 杜撰主張） | 0/2 | 0/2 |
| 攔到的旗標 | 4 筆，全是取景/覆蓋問題 | 4 筆，同左 |

兩型失敗各有結構性原因：RDH-3092 是**真舊損掩護真新損**——「有既有凹陷」主張
本身為真，查核主張文字攔不到疊加的新損；RCG2235 那筆杜撰主張，
盲列舉探針（不給主張、只問「這區有哪些痕跡」）證實兩個模型**無提示下也會在
借車照同位置「看見」人工確認不存在的刮痕**——不是確認偏誤，是模型家族層級的
一致性感知錯誤。

> **★ 五次實驗的總結論：同模型家族的第二意見不是獨立意見。**
> 查核者與被查核者共享同一套感知偏誤，錯誤會被「獨立呼叫」原樣複現。
> 完整數據見 `reverse_check.py` 檔頭與 `reverse_check_results*.json`。
> （此結論隨後被 v6 精確化：失敗的是「拿主張去問」的形態，不是同家族查核本身——見下節。）

### ⑥ v6 盲列舉差分：六次嘗試中第一個存活的機制

第六次嘗試（`blind_enumeration.py`，2026-08-28）改變的是**形態而非模型**：
不給任何主張，對借車照與還車照**分開、各自獨立**跑同一份盲列舉 prompt
（目標 panel 劃 3×3 網格、中性形態詞、逐格記錄），再由程式端差分、兩模型取格位交集。
核心假設：一致性幻覺兩邊都出現 → 差分為零；真新損只在還車照出現 → 產生訊號。

實驗設計預先註冊四項證偽條件（讀數不穩／幻覺不一致／目標仍無訊號／誤旗過多），
先跑 50 次讀數穩定性標定（門檻由實測變異推導，非憑感覺設），再對 30 筆
「判無新損＋帶既有損主張」案件差分。**四項條件全數未觸發**：

| 檢驗 | 結果 |
|---|---|
| RDH-3092（唯一漏抓，真新損疊真舊損） | **兩模型各自獨立指向同一格 A2**，佔用＋延伸雙訊號——抓回 |
| 一致性幻覺（借車照 B3 深色痕，10 次列舉 9 次出現） | 借/還兩邊都被列出 → **差分為零，自我抵消成立** |
| clean 誤旗 | 2/28（7.1%），皆為送人工複核旗標而非自動改判 |
| 讀數穩定性 | flash 佔用不一致 20.0%（恰在邊界）、pro 4.8%——交集設計讓 flash 噪音無害化 |

**合併效果（若接入）**：Recall 95.5% → **100%**（22/22）、自動判定 FPR 維持 0%，
代價是 21% 的案件多 4 次呼叫＋7.1% 的既有損案送人工掃一眼。

> ⚠️ 誠實限制：n=30 是本資料集該類案件全體，但絕對數小、誤旗率信賴區間寬；
> 接入前須照下方規範跑 shadow mode。相鄰格容忍交集（可多抓回一筆非生產相關的
> 真損）經敏感度分析後**不採用**——誤旗率升到 28.6% 且屬事後調參。
> 完整數據與原始列舉輸出見 `blind_enumeration.py` 檔頭與 `blind_enum_*.json`。

方法論結語：五次失敗＋一次存活畫出同一條線——**改判定當下的 prompt 全敗，
判定之後的獨立層（S6/S7 可解釋性、v6 差分查核）全部可運作**。
差別從來不是措辭，是有沒有動到判定本身。

### ⑦ 已整合進監理台的部分

五次實驗證明「動判定本身的改法全部落敗」，但**判定之後**的加值層是純加分——
它們吃的是判定結果不是照片，不影響 95.5%／0%：

| 層 | 位置 | 效果 |
|---|---|---|
| **S6 估價分流** | `disposition.py` → `server.enrich()` → 案件卡「維修估價與處置建議」 | 每筆損傷給維修動作＋級距＋金額區間；22 件可索賠案件合計 **NT$163,000–525,000** |
| **S7 三對象文案** | `POST /api/notify` → 案件卡「✉ 產生三對象通知文案」 | 用戶／客服／派工單三種語氣，附程式面 grounding 查核（防杜撰金額與歸咎表述） |
| 索賠經濟性 | `disposition.decide()` | 估價低於處理成本自動標記「不值得索賠」——**能算出不值得追也是系統價值** |

估價全部走純規則零 API，同一種損傷永遠得到同一個報價（可稽核）；文案是按需的一次呼叫。
整合過程修掉三個會出錯的地方：
- **塑膠保桿被當鈑金報價**（無 panel → 無材質 → 落進最貴級距）：改由 `location` 文字推分區，
  保桿刮痕從「整片烤漆 5,000–15,000」修正為「保桿修補烤漆 1,500–5,000」
- **「破損」一律報換件**（12,000–40,000）：改由 severity 調節，medium 以下降為板件修補
- **「輪圈：整片烤漆」**：鋁圈／玻璃／燈殼加專屬規則，不再套鈑件邏輯

## 評測與版本管理規範（改 prompt 前必讀）

上面五次證偽能成立，靠的是同一套評測紀律。日後任何 prompt／門檻／模型改動一律照此執行：

1. **全量才算數**：任何改動都要跑滿 141 組借/還配對。**12 組小樣本會嚴重誤導**——
   v4 修法在小樣本上曾是 100%/0% 完勝，全量後是用 4 筆高信心杜撰換 1 筆真損。
2. **對照人工重標，不是原始索賠標籤**：`compare_prompts.py --b eval_results_<tag>.json`，
   看「vs 人工重標」那一列（n=138）。原始標籤有 4 筆「未索賠實為真損」，會把 TP 記成 FP。
3. **變體與現行並存，單一事實來源不動**：新 prompt 用 `--tag` 寫獨立結果檔
   （progress JSONL 支援斷點續跑），`results_config.py` 只在全量勝出後才切換。
   四個變體（v2/v4/v5/reverse_check）至今全部落敗，`FINAL_RESULTS` 從未動過。
4. **每筆判定可追溯**：結果檔記 model／prompt 變體 tag／門檻版本；
   負面結果寫進對應模組檔頭（`detect_v2.py`／`run_eval_gemini.py`／`cv_prefilter.py`／
   `reverse_check.py`），**避免有人重跑已證偽的路線**。
5. **Ablation 逐項記錄**：每加一條規則量一次，本專案的實測軌跡——

   | 變更 | Recall | FPR | 結論 |
   |---|---|---|---|
   | 現行 prompt（EXIF 轉正 + Pro 級聯） | 95.5% | 0% | ★ 採用 |
   | v2 規格版整包 | 100% | 3.5% | 落敗（高信心杜撰） |
   | v4 只移植既有損舉證 | 95.5% | 3.5% | 落敗（舉證欄位被杜撰填滿） |
   | v5 只加排除理由欄位 | 81.8% | 2.6% | 落敗（解釋拖垮推理） |
   | reverse_check 外部驗證層 | 攔截 0/2 | — | 落敗（命題確認形態不可用） |
   | v6 盲列舉差分層 | 合併 100% | 0%（+7.1% 送審） | ★ 存活，待 shadow mode |

6. **上線前 shadow mode**：新版本與舊版本同時執行、只用舊版做決策，比對判定差異
   與人工核可率一週，確認無退化才切換（對應監理台的 append-only `decision_events`，
   翻轉紀錄本身就是評測資料）。

## 訓練標籤累積機制（為日後自訓模型鋪路）

VLM API 判定準確、上線快，但長期而言自訓模型才是成本與延遲的解方。
問題在於自訓模型需要大量人工標註資料——而**監理台的複核作業本身就在產生這批資料**。

每一次人工裁決（確認車損／駁回誤報）都會 append 一筆 `decision_events`，存下：

| 欄位 | 內容 |
|---|---|
| `label` | 人工真值（confirm=1／reject=0／retake=NULL 不表態） |
| `ai_found` / `agreed` | AI 當時的判定，以及是否與人工一致 |
| `photos` | 照片絕對路徑（訓練時據此讀圖） |
| `boxes` | AI 標註框 box_2d |
| `assessment` | AI 完整判定含理由 |
| `note` | 稽核員備註（難例說明） |

**稽核員本來就要看這些照片，所以這批標籤的邊際成本是零。**
資料表刻意 append-only：改判、復原的歷程本身就是難例訊號，覆蓋掉就永遠救不回來。

```bash
# 查看累積現況（監理台統計列也會即時顯示）
curl localhost:8000/api/labels/stats

# 匯出訓練資料集
python3 pipeline/export_training_labels.py                  # JSONL
python3 pipeline/export_training_labels.py --format coco     # COCO 偵測格式
python3 pipeline/export_training_labels.py --disagreed-only  # 只要 AI 判錯的（難例挖掘）
```

以本資料集流量估算（4,820 單／日 × 4 方位 ≈ 19,280 組／日），
車損率 0.5% 時約 **52 天**即可累積 5,000 個正樣本，達偵測模型訓練門檻。

> ⚠️ 匯出的 `box_2d` 由 VLM 產生、人工僅確認「有無車損」而非框的精確度。
> 正式訓練偵測模型前建議先人工修框，或當作弱監督（weak supervision）使用。
> 「有無車損」二分類則可直接使用。

## 自訓 CV 模型（流程驗證）

`training/` 打通了「監理台標籤 → 訓練 → 評估 → 推論」整條路，並誠實量測現況：

| 指標 | 自訓 ResNet18 | 現行 VLM 級聯 |
|---|---|---|
| ROC-AUC（5-fold 車輛分組交叉驗證） | **0.594**（隨機 = 0.50） | — |
| Recall / FPR | 45.5% / 22.4% | **95.5% / 0%** |

**結論：現階段 VLM 完勝，自訓模型不應接入主流程。**
瓶頸是資料量（僅 22 個正樣本）而非程式——ablation 顯示凍結 backbone 的
linear probe（0.611）反而略優於全微調（0.594），是典型過擬合。

等監理台累積到數千筆標籤後，同一支腳本可直接重跑。詳見 [training/README.md](training/README.md)。
